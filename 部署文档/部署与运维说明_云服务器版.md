# 学管 SmartEdu —— 云服务器部署与运维说明（彻底突破三约束）

> 目标：把系统部署到云服务器，实现「免 bat、开机即用、24/7 常驻、手机/异地任意网络访问」。
> 相比本机 + 穿透方案，上云是**最彻底**的破约束方式：不再依赖你的电脑开机，评委/学生全球可达。
> 前提：本项目已自带 `Dockerfile` 与 `docker-compose.yml`，本次已修复使其可正常构建（见文末「本次已修复项」）。

---

## 一、为什么上云能一次性破三个约束

| 原约束 | 根因 | 上云后 |
|--------|------|--------|
| 每次开 bat | 无进程守护 | Docker + `restart: unless-stopped` 守护，崩溃自动拉起 |
| 主机不能关机 | 服务跑在桌面 | 云服务器 24/7 在线 |
| 师生必须同局域网 | 无公网地址 | 云服务器自带公网 IP，任意网络可达 |

已验证：`server.js` 监听 `0.0.0.0:3100` 与 `0.0.0.0:3543`，**容器内、公网均可直接访问，无需改代码**。

---

## 二、选型建议（成本与合规）

- **云厂商**：阿里云 / 腾讯云「轻量应用服务器」2C2G，Ubuntu 22.04，活动价约 **40–90 元/月**；学生认证更便宜。
- **域名**（推荐但不强制）：用于 HTTPS 与好记地址。国内解析到服务器公网 IP **需要 ICP 备案**（介意可先用 `IP:端口` + 云免费证书，或走 Caddy 自签/Let's Encrypt）。
- **备案提示**：若用国内服务器 + 域名提供公开 Web 服务，需完成 ICP 备案；纯 IP 访问通常可暂不备案（以厂商规则为准）。

## 三、服务器端一键安装 Docker

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER      # 退出重登后免 sudo
docker compose version             # 确认安装成功
```
> GFW 拉不到 `get.docker.com` 时，改用国内源（以阿里云为例）：
> ```bash
> sudo apt update
> sudo apt install -y ca-certificates curl gnupg
> sudo install -m 0755 -d /etc/apt/keyrings
> curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
> echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://mirrors.aliyun.com/docker-ce/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
> sudo apt update && sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
> ```

## 五、配置 compose 环境变量（关键）

`docker-compose.yml` 会自动读取同目录的 `.env`（即项目已有的那个 `.env`，compose 用它做变量插值）。需确认/修改：

- **`DEFAULT_ADMIN_PASSWORD`**：当前在 `.env` 里是**注释掉的**。云上若用「空卷起新库」，必须先设一个 ≥8 位强密码（首启动创建 admin）；若用 `docker cp` 注入现有 `data.db`（已含 admin），设了也无害（库里有 admin 就跳过创建）。
- **`JWT_SECRET`**：已是随机值，可保留。
- **`ZHIPU_AI_API_KEY`**：已在 `.env`，会自动注入容器，AI 问答功能可用。
- 端口保持 `PORT=3100` / `HTTPS_PORT=3543`。

> ⚠️ `.env` 含密钥，请勿提交到公开仓库。本项目 `.dockerignore` 已排除 `.env` 不进镜像。

## 八、HTTPS（手机/异地用 https 访问，浏览器不报红）

**方案 A：Caddy 反代自动申请 Let's Encrypt（免费 + 自动续期，推荐）**
```bash
sudo apt install -y caddy
```
`/etc/caddy/Caddyfile`：
```
your.domain.com {
    reverse_proxy localhost:3100
}
```
`sudo caddy reload` 后访问 `https://your.domain.com` 自动签证书。安全组只开 80/443，不对外暴露 3100/3543。

**方案 B：云厂商免费证书 + CDN/CLB**：腾讯云/阿里云控制台申请 DV 免费证书，配到负载均衡或 CDN，回源到服务器 3100。

**方案 C（临时演示）**：直接用 `https://<公网IP>:3543`，自签证书浏览器会警告，点「高级→继续」即可。仅限临时演示，不专业。

## 九、防火墙 / 安全组

- 云控制台安全组：入站放通 **80、443**（用 Caddy 时）；若要临时直连 3100 也放通 3100（不建议长期直连）。
- 服务器本地：`sudo ufw allow 80,443,22`。
- admin 强口令已设；演示结束可改口令或 `docker compose down` 关停。

## 附：本次已修复项（让上云能正常构建/运行）

3. **新增 `.dockerignore`**：排除 `node_modules`、本地 `config/data.db`、`*.log`、`.env` 等，避免把 10MB 业务库与依赖打进镜像、拖慢构建并误带密钥。
4. **compose 已具备**：`restart: unless-stopped`、命名卷持久化、健康检查、必需环境变量校验——开箱即用。
