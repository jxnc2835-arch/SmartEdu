# 学管 SmartEdu —— 性能评估 & 启动/非局域网登录操作卡

> 评估与说明基于 2026-11-17 实机实测（数据 2.68 万行 / 10.8MB，Node v22.22.2，端口 3100/3543）。
> 详细运维手册见 `部署文档/部署与运维说明_Windows公网版.md`（本文是"按场景快速操作"的精简版）。

---

## 一、整体性能评估（实机实测）

### 1.1 数据量级
| 指标 | 数值 | 结论 |
|------|------|------|
| 数据库体积 | 10.8 MB（better-sqlite3 WAL） | 很小，内存库 + 落盘都轻松 |
| 总行数 | ≈ 26,813 | 小数据集 |
| 主要表 | records 23,505 / absence_alerts 896 / visitors 574 / tasks 335 / students 159 | records 占 88%，是主要负载 |

### 1.2 接口响应耗时（本地实测，含网络往返）
**全部接口都在 5~80ms 区间，非常快。** 最重的计算密集接口（LSTM/ARIMA 预测、全量统计）也只有 25~50ms。

| 接口类型 | 代表接口 | 耗时 |
|---------|---------|------|
| 列表查询 | `/api/students`、`/api/dorms`、`/api/leaves` | 4~12ms |
| 记录查询 | `/api/records?type=checkin&limit=200` | 36ms（最慢的常规查询） |
| 计算密集 | `/api/predict/checkin-trend`（时序预测） | 25~30ms |
| 计算密集 | `/api/predict/at-risk`（高风险预测） | 20~49ms（首调略慢，有模型加载） |
| 统计 | `/api/stats/overview` | 20~80ms（波动最大，统计聚合） |
| 新增功能 | `/api/health/full`、`/api/ai/usage` | 6~21ms |

### 1.3 并发能力
- **20 并发全部 200**，单请求 19~54ms，墙钟总耗时 ~1 秒完成。
- 单进程 `fork` 模式足够支撑"一个学院几十人"规模。

### 1.4 资源占用
- 服务进程 RSS ~49MB、堆 ~5MB（启动稳定态），**极轻**，老旧电脑也跑得动。
- 内存库（sql.js）+ better-sqlite3 即时落盘（P0 已修），断电丢失窗口 ~0.3s。

### 1.5 瓶颈与隐患（按优先级）
| 级别 | 项 | 说明 | 建议 |
|------|----|------|------|
| P1 | `/api/stats/overview` 波动大（20~80ms） | 统计聚合对全量 records 扫描，数据量增长后会线性变慢 | records 超过 ~20 万行前无需处理；届时给 date/student 建复合索引 + 结果缓存 |
| P2 | 预测首调略慢（49ms） | 模型/历史数据首次加载 | 可加"模型预热"（服务启动时跑一次空预测） |
| P2 | 单进程无横向扩展 | 单 fork，CPU 密集时单核 | 当前规模足够；若多人同时跑 AI 问答再考虑 `cluster` 多实例 |
| P3 | 内存库架构固有取舍 | kill -9 丢最后 ~0.3s | better-sqlite3 即时同步已把窗口压到极小，可接受 |

**总体结论**：以 2.6 万行数据量，性能**远未到瓶颈**，响应毫秒级、并发 20 轻松、内存占用极低。当前架构（内存库 + WAL 落盘）对"学院级自用"绰绰有余，**无需为性能做任何改造**。

## 二、更便捷的启动方式（按场景选）

项目已配好 4 种启动入口，**无需写新代码**，按你的场景挑一个：

| 场景 | 用哪个 | 一条命令 | 特点 |
|------|--------|---------|------|
| ① 临时试一下 | `node server.js` | 直接前台跑 | 关掉终端就停，开发调试用 |
| ② 本机/局域网常驻（最省心） | **`server.bat`** | 双击 → 选 1 启动 | 自动清理 3100 端口残留、验证起没起、打印手机访问指引；菜单还带 停止/状态/开浏览器/跑测试 |
| ③ 本机 24h 守护 + 开机自启（不挂公网） | PM2 | `pm2 start ecosystem.claw.config.js` | 崩溃自动拉、`pm2 save` 后开机自启；**不需要 cpolar token** |
| ④ 出公网 + 一键全配好 | **`deploy.bat`**（管理员运行） | 双击 | 装 PM2 → 起服务 → 固化为开机自启服务 → 装 cpolar → 起隧道，一次到位 |

**推荐**：
- 只是想自己用/校内用 → **场景② `server.bat`** 双击最方便，全程不用记命令。
- 想让电脑关机后自动起、长期在线 → **场景③**（PM2，免折腾穿透）。
- 要让老师学生在**任何网络**都能登 → **场景④ `deploy.bat`** 一次搞定。

> 端口冲突？`server.bat` 启动前会自动 `taskkill` 掉占 3100 的旧实例，`server.js` 还有 EADDRINUSE 自增兜底，基本不会卡住。

## 三、非局域网（异地/手机流量/外网）登录 —— 操作说明

核心思路：**主机留在辅导员那台 24h 在线的 Windows 电脑**，数据不出内网；用**内网穿透**把本机 `localhost:3100` 映射成公网 HTTPS 地址，师生开链接即用，**不用连校园网、不用装软件、不用改路由器端口**。

### 3.1 主推：cpolar（国产穿透，国内稳）
1. **装 cpolar**：官网 https://www.cpolar.com 注册 → 下 Windows 客户端安装（自动进 PATH）。
   （`deploy.bat` 已内置自动下载安装，跑过它可跳过这步。）
2. **绑 token（一次性）**：`cpolar authtoken <你的token>`（token 在 cpolar 控制台复制）。
3. **起穿透并固化**：
   ```
   cd D:\学管SmartEdu
   pm2 start ecosystem.cpolar.config.js
   pm2 save
   pm2 logs smartedu-cpolar        # 日志里找 https://xxxx.cpolar.io 公网地址
   ```
4. 把日志里的 `https://xxxx.cpolar.io` 发给师生，手机/异地直接开。

**地址会变怎么办**：免费版公网地址约每 24h 变一次。
- 临时用 → 每次从 `pm2 logs smartedu-cpolar` 拿最新地址。
- 要固定 → cpolar 控制台「保留二级子域名」（付费档），把 `ecosystem.cpolar.config.js` 的 `args` 改成 `http -subdomain=你的固定名 3100`，再 `pm2 restart smartedu-cpolar`。

### 3.2 备选：Cloudflare Tunnel（免费）
cpolar 不稳时可用（国内终端有时偏慢）：
```
winget install Cloudflare.cloudflared
pm2 start ecosystem.tunnel.config.js    # 快速隧道，日志找 https://xxxx.trycloudflare.com
pm2 save
```

### 3.3 关键注意事项
- **数据隐私**：公网地址任何人都能扫到。对外务必靠系统自带的登录鉴权（admin/counselor/student 角色）当第一道防线；可在 cpolar 控制台开「隧道认证/访问白名单」进一步限流。人脸/签到属敏感数据，公网只放脱敏演示数据。
- **不用时关公网口**：`pm2 stop smartedu-cpolar`（保留院内访问，只断公网出口）。
- **admin 密码**：公网暴露下务必用强口令，别改回弱口令。
- **局域网 IP 失效**（若有人仍用 `http://内网IP:3100`）：路由器做 DHCP 静态保留，或用 cpolar 公网地址彻底摆脱内网 IP 依赖。

## 四、一句话总结
- **性能**：毫秒级响应、20 并发轻松、占用极小，当前规模**无需改造**；数据涨到 20 万行前不用管统计索引。
- **启动**：自用双击 `server.bat`，长期在线 PM2，出公网双击 `deploy.bat` 一键全配好。
- **非局域网**：cpolar 穿透把本机映射成公网 HTTPS，师生零安装开链接即登；固定地址走付费子域名。
